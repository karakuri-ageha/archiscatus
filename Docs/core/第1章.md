## 第1章：ランクシステム設計論

### 1-1. ランク名に必要な二つの機能

ランク名が機能するために必要な要素は「序列の伝達」と「格の雰囲気の伝達」の二点のみである。S〜Fのようなアルファベット等級はこれを最小コストで達成する手段であり、唯一の正解ではない。独自ワードによるランク命名は、序列の即時伝達を犠牲にする代わりに、世界観の深度と物語の駆動力を獲得する。

|機能|内容|例|
|---|---|---|
|序列の伝達|誰が上で誰が下かがわかる|S＞A＞B、龍＞玄＞麒|
|格の雰囲気の伝達|名前からどのくらいの存在かが感じ取れる|「Sランク」→強い、「龍」→頂点感がある|

この二つさえ満たしていれば、ランク名はアルファベットでも花の名前でも幻獣でも何でもよい。

### 1-2. 二つの設計方向

|方向性|特徴|利点|欠点|
|---|---|---|---|
|即時理解型（S〜F等）|既存の共通認識に依存|説明不要、直感的|没個性、世界観が乗りにくい|
|独自命名型（本資料の方向）|世界固有の言葉で構成|世界観の深度が増す、物語を駆動する|初見で序列がわからない、一度は説明が必要|

本資料は独自命名型を中心に扱うが、対外ランクとして即時理解型を併用する二層構造を推奨する。これにより、作中の一般社会に対しては即時理解型で機能させ、冒険者同士や物語の深層では独自命名型の豊かさを活用できる。

### 1-3. 独自命名型の強み

独自命名型の最大の強みは、ランク名自体が会話のきっかけになることにある。「お前何ランク？」「鵺」「は？」というやり取りが発生する時点で、キャラクター間の会話が自然発生し、その会話がそのまま世界観の説明シーンとして機能する。ランク名が物語を駆動するエンジンになるという、極めて贅沢な設計である。

また、直感的に格上に見える名前を下位に配置する「逆転構造」を導入することで、「なぜ？」という問いが誘発され、その回答が世界観の説明になる。ランク名一つで物語への導入装置が成立する。

### 1-4. 最適な段階数

|段階数|向いてる用途|理由|
|---|---|---|
|5段階|ゲーム・シンプルな物語|人間が直感的に把握できる上限が「5±2」。底辺・下位・中位・上位・頂点で綺麗に収まる|
|7段階|長編小説・RPG|マジカルナンバー7に収まる。奇数のため中間点が存在し、上下に3段階ずつで成長余白と格上脅威を同時に描ける|
|9段階|壮大な世界観・長期連載|上下に十分な幅があり、同ランク内の格差も描ける。全ランクを使い切るには相当な尺が必要|

7段階が汎用的には最も扱いやすい。理由は、人間の短期記憶の「マジカルナンバー7」に収まること、奇数のため「ど真ん中」が存在し主人公の現在地を置きやすいこと、上下に3段階ずつあるため成長の余白と格上の脅威を同時に描けることの三点である。

### 1-5. 構造パターン

ランクシステムの構造は大きく三つのパターンに分類される。

| パターン | 構造                      | 特徴                                                       | 総段階数の算出            |
| ---- | ----------------------- | -------------------------------------------------------- | ------------------ |
| 単層型  | メインランクのみ                | 最もシンプル。短編や背景設定向き                                         | メインランク数            |
| 連結型  | メインランク＋サブランク            | メインランク内にサブランクを内包する二層構造。同ランク内の差異を描ける                      | メインランク数×サブランク数     |
| 分岐型  | 属性別に複数のメインランクテーブル＋サブランク | 属性ごとに異なるランク名を持つ。系統間の対比が物語を生む。サブランクは系統間で共通にしても系統ごとに変えてもよい | メインランク数×サブランク数×系統数 |

単層型は軽量で扱いやすい。連結型はメインランクが「何者であるか」、サブランクが「どこまで進んだか」を分離して記述できるため、同じランクでも重みが異なるキャラクターを描ける。分岐型は系統間の対照が自然と物語の対比を生むが、管理の複雑さも比例して上昇する。

### 1-6. モジュラー設計思想

本資料のランクシステムは、モジュラー設計を採用している。各機能を独立したモジュールとして定義し、作品ごとに必要なモジュールを選択して接続する方式である。

|性質|内容|
|---|---|
|独立性|各モジュールは単体で機能できる|
|互換性|どのモジュール同士でも接続可能|
|選択性|必要なモジュールだけを選んで使用する|
|拡張性|新規モジュールの追加が既存構造を壊さない|

この設計により、短編で使う最小構成から大長編のフル構成まで、同じ設計資料から構築できる。特定の作品に縛られず、誰でも自分の世界観に合わせてカスタマイズが可能である。
